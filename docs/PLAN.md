# KeyFlux：Rust 实现 macOS Shift 切换与中/英键大写的方案计划

日期：2026-10-22  
状态：Shift / Caps 仍需实机调试。用户要求先增加可开始、停止、退出的原生控制窗口，暂停新版 DMG 制作；真实键盘 / 输入框效果、硬件状态与资源指标尚未验收。

## 1. 目标与本次边界

在当前已经执行 `cargo init` 的 KeyFlux 项目中，分阶段实现一个 macOS 用户会话内运行的 Rust 后台工具：

1. 单独按下并松开 Shift，在系统 ABC 与 Apple 拼音之间切换。
2. 键盘左侧的“中/英”键作为 Caps Lock：短按开启大写，再按关闭，不再承担语言切换。
3. 根据最新要求提供简易原生 GUI：默认不监听，显示状态、权限与错误，提供开始监听、停止监听、检查权限、退出程序。关闭窗口或 ⌘Q 停止监听并退出，不继续隐藏运行。
4. 原无 GUI 阶段的内存目标为 15 MB。当前 AppKit 控制窗口与监听处于同一进程，必须重新测量整个进程的 RSS；不通过拆出辅助进程来改变口径，空闲 CPU 仍要求接近 0。
5. 单进程、单个主要事件循环，不引入 Tokio、Web 框架、数据库、网络请求或常驻辅助服务。

本轮只补控制窗口及对应监听生命周期，不重新修改 Caps 行为或继续发行。引入 objc2 / Foundation / AppKit Rust 绑定，保持单进程、单主线程；AppKit 驱动主 RunLoop，开始按钮只注册原生来源，停止按钮注销全部来源。错误通过一次性 CFRunLoopSource 通知延后清理，不轮询状态，也不在执行中的键盘回调里释放回调对象。旧版无 GUI / 不依赖 AppKit 的说明仅适用于历史方案。

用户所说的“与 Windows 对齐”，本方案限定为 Shift 的单按切换以及 Caps Lock 的大小写行为，不扩展为整套 Windows 键盘映射。

## 2. 原项目可复用的设计

参考项目：以 KeyFlux 项目根目录为基准的同级目录 `../ShiftIME`，来源为 [TW527E/ShiftIME](https://github.com/TW527E/ShiftIME)。本次阅读的提交为 `d3e8d70420bc405fd178a31c372f4bdf3ff9aa99`。

| 原项目文件 | 已确认的职责 | KeyFlux 的处理 |
| --- | --- | --- |
| `Sources/ShiftIME/GlobalKeyboardMonitor.swift` | CGEventTap、事件暂存补发、超时恢复 | 保留核心思路，改为 Rust 与原生 API 集成 |
| `Sources/ShiftIMECore/ShiftGestureStateMachine.swift` | 判断单按 Shift、避免组合键误触 | 保留纯状态机划分 |
| `Sources/ShiftIME/InputSourceManager.swift` | TIS 查询选择、切换确认与有限重试 | 保留来源确认，重新设计无窗口的完成条件 |
| `Sources/ShiftIMECore/InputSourceSelectionPolicy.swift` | 根据来源 ID 与选中状态判断结果 | 保留，不能拿 ABC 底层布局代替拼音模式判断 |
| `Sources/ShiftIME/AccessibilityPermission.swift` | 辅助功能与输入监控权限 | 保留必要检查，改为终端诊断 |
| `Sources/ShiftIMECore/ApplicationBypassPolicy.swift` | 远程桌面和游戏放行 | 作为后续兼容性参考，不默认搬入整套识别系统 |
| 设置窗口、状态栏、HUD、图标与 DMG | 应用界面与发行 | 不纳入本版 |

原项目没有中/英键改为 Caps Lock 的实现，这部分属于新增功能。

原项目虽然平时不轮询输入法，但切换期间会短暂查询状态。KeyFlux 同样采用“空闲无轮询，发生操作后有限确认”，而不是禁止任何计时器。

原项目的透明窗口焦点转移与本项目的无 GUI 目标冲突，不直接移植。如果无窗口方案在某些应用中无法使拼音真正生效，记录为兼容性问题，继续研究原生输入上下文机制；不能只依据输入法图标判定成功，也不能偷偷添加窗口绕过。

## 3. 按键行为约定

### 3.1 Shift

| 操作 | 目标结果 |
| --- | --- |
| ABC 下单按左或右 Shift | 切到配置的 Apple 拼音来源 |
| 拼音下单按左或右 Shift | 切到 ABC |
| Shift + 字母、数字、符号 | 正常输入，不触发语言切换 |
| Shift + Command / Control / Option 组合 | 原样保留快捷键行为 |
| Shift + 鼠标点击或滚动 | 不触发语言切换 |
| Shift + Space | 保留系统原行为，不移植原项目的全半角功能 |
| 左右 Shift 同时按住再松开 | 最后一个松开时至多切换一次，期间有组合操作则不切换 |
| 密码框等安全输入环境 | 放行，不推断缺失的字母事件，不触发自定义切换 |
| 当前输入来源不是目标 ABC / 拼音 | 默认放行，不把其他语言强行切走 |

第一版沿用“没有参与其他操作的完整按下/松开周期”识别单按，不新增按住时长阈值。单独长按再松开也算一次；如果后续希望只接受短按，再调整约定。

### 3.2 中/英键与 Caps Lock

这里的“中/英”指兼作 Caps Lock 的物理按键，不是屏幕上的输入法按钮，也不是 Fn / 地球键。正式接入前先确认本机内置键盘及需要支持的外接键盘实际事件，不能只凭键帽文字确定键码。

目标行为：

| 初始状态与操作 | 目标结果 |
| --- | --- |
| 大写关闭，短按中/英 | 开启持续大写，无需长按 |
| 大写开启，再短按中/英 | 关闭大写，固定进入小写 ABC |
| 大写开启，输入字母 | 输出大写拉丁字母 |
| 大写开启，输入数字或普通标点 | 保持正常数字、标点，不把它们变成 Shift 符号 |
| 大写开启，Shift + 字母 | 以临时小写为 Windows 风格目标；需验证 macOS 原生行为，不能假定天然一致 |
| 大写开启，单按 Shift | 关闭 Caps Lock，留在小写 ABC；再次单按才切中文 |
| 按住中/英不松开 | 一个物理按压周期只翻转一次，不能因重复事件来回翻转 |

Caps Lock 是独立的锁定状态，不能通过“永久按住 Shift”模拟，也不采用全局替换已输入文本的方式实现。

当前实现采用中文拼音、小写 ABC、大写 ABC 三个目标状态。Caps 只控制英文大小写，Shift 负责中文与小写英文之间的切换；保持此前确认的大写下单按 Shift 进入小写 ABC。大小写使用相同的 ABC 字母规则，不依赖拼音内部英文模式。

1. 拼音或小写英文下按 Caps：真实 Caps 开启，通过现有切换协调器进入大写 ABC。
2. 大写下再按 Caps：真实 Caps 关闭，固定进入小写 ABC，不保存或恢复之前的拼音。
3. 小写 ABC 下单按 Shift 进入拼音；拼音下单按 Shift 进入小写 ABC。切回拼音必须以输入框实际出现中文候选词验收。
4. 实际接管采用非独占 HID，不引入驱动、root 服务或持久键位修改。

## 4. Caps Lock 的优先验证事项

Apple 的输入法设置提供“使用大写锁定键切换至和切换自……”选项。开启时，短按可承担语言切换，长按才开启持续大写。这是系统层行为，与 ShiftIME 的 Shift 状态机是两回事。

实机前置条件：用户手动关闭该语言切换选项。KeyFlux 使用 IOHIDManager 监听 UsagePage=7、Usage=0x39 的物理 Caps 输入，再使用 IOHIDSystem 管理真实 Caps。程序不自行修改全局偏好、HID 映射或系统配置。

随后必须区分三层状态：

- 物理键是否产生了可观察的按下/松开或锁定变化事件。
- 系统的 Caps Lock 状态是否真实改变。
- 当前拼音/ABC 与目标应用是否按预期输出大写。

仅设置某个 CGEvent 的 Caps Lock 标志，或在 Rust 中维护 `caps_enabled`，不等于系统锁定状态、指示灯和后续按键都已经同步。

当前代码不再只依赖 CGEventTap 的 Caps flagsChanged 判断物理短按。非独占 HID 直接报告按下 / 松开，按设备去重，并在设备移除时清理未松开记录；时间戳早于监听创建的报告不触发新开关。实际键盘是否报告该 Usage、是否提供可靠时间戳仍待实机确认。

已按本机 SDK 接入 `IOHIDGetModifierLockState`、`IOHIDSetModifierLockState`，使用 Caps selector=1。同时读取 `CGEventSourceFlagsState(kCGEventSourceStateCombinedSessionState)`，要求底层与会话 Caps 都达到目标。实机反馈证明，仅因会话值已关闭就确认成功会跳过底层关闭写入；输入来源显示拼音也不能作为真实组词生效的证明。原生 Caps 状态事件按逻辑目标修正后放行，HID 仍独立负责物理按压去重。最后一个物理 Caps 松开后才安排确认；每轮最多写 4 次、300ms 窗口，失败后分别等待 100ms、200ms 进行第二、第三轮，最多累计写 12 次。重试期间保留监听、有界暂存输入，Caps 相关来源切换在确认成功后才启动其自身截止时间。成功记录恢复；三轮耗尽后停止并报告两个读数、累计写入和轮次。停止、安全输入或新目标会取消旧重试，不重新注册整套监听。原生 API 调用失败保留停止策略；硬件键盘灯与具体输入框表现仍需分别验收。

这里的会话状态是全部事件源在当前登录会话的组合修饰键状态，不能把它宣称为硬件灯状态。[Apple：CGEventSourceStateID](https://developer.apple.com/documentation/coregraphics/cgeventsourcestateid)

第一阶段的输出是明确可行的事件与系统状态控制路径。如果必须依赖全局键位修改、额外权限或辅助进程才能实现，应先更新方案说明影响，再决定是否继续，不能暗中扩大架构。

## 5. 技术架构与模块

```text
键盘事件 ───────────────┐
输入来源变更通知 ───────┤
切换期间的一次性计时器 ─┤
                      ↓
               单个 CFRunLoop
                      ↓
               事件分类 / 放行
                      ↓
          Shift 状态机 + Caps 状态协调
                      ↓
              输入来源切换协调器
                      ↓
        TIS 选择 / 结果确认 / 按顺序补发
```

默认使用普通用户会话中的 session event tap，不使用需要更高权限的 HID 入口 tap。状态集中在事件循环线程中，避免共享可变全局对象、锁和重复执行器。

当前代码骨架采用以下分层结构；启动入口、依赖组装、应用流程、领域规则和 macOS 适配分别管理：

层次依赖：`main → bootstrap → application → domain / infrastructure`；macOS 适配器可以使用领域模型与统一错误，领域层不得反向依赖应用层或基础设施。当前保持一个 Cargo package；不引入 Spring 式自动注入、Web Controller、数据库 Repository 或多 crate workspace。应用层先使用具体系统适配器，尚未引入 trait 端口；只有后续出现明确替换需求时再抽象。

后续原生 FFI 声明与资源包装放在 `infrastructure/macos/` 内，按实际系统 API 分拆，避免重新汇集到一个无边界的公共工具文件。

| 系统能力 | 初选机制 |
| --- | --- |
| 键盘监听 | Core Graphics CGEventTap，只订阅必要的键盘事件 |
| 等待事件 | Core Foundation CFRunLoop |
| 输入来源获取和选择 | HIToolbox / TIS 系列 API |
| 输入来源变更 | TIS 分布式通知，可评估 Core Foundation 通知中心接入 |
| Shift 鼠标组合排除 | Shift 按下与松开时读取窗口服务器事件计数，不订阅每次鼠标移动 |
| 安全输入判断 | 系统安全输入状态接口，按需检查 |
| Caps Lock 控制 | 非独占 HID 物理输入 + IOHIDSystem 真实状态写入及回读 |

依赖选择原则：先核实 API 覆盖和所有权，再比较小型原生绑定与局部手写 FFI。`cgevents` 只作为候选，不因示例提及就直接加入；本次未完成其 API 与依赖评估，不锁定 crate 或版本。TIS 等缺口可以局部 FFI，不为少量调用引入整套 GUI 框架。

所有 `unsafe` 集中在系统适配层；区分 Copy/Create 获得的拥有引用与 Get 获得的借用引用。事件补发队列持有的对象、通知注册、计时器和 event tap 均需有明确释放路径；Rust panic 不得跨越 C 回调边界。

## 6. 切换时序与异常处理

### 6.1 切换状态

采用 `Idle → Selecting → Confirming → Completed / Failed`。只有真实的物理按键状态机可以发起操作，补发事件带有进程自定义标记并原样放行，防止递归触发。

- 稳态不重复查询输入法，只响应系统通知和用户事件。
- 切换期间可以使用有截止时间的一次性计时器；没有常驻唤醒循环。
- 只根据目标来源 ID 和选中状态判断来源选择完成；实际输入框生效还需应用兼容性验收。
- 当前 ID 已是目标但尚未选中时等待，不反复选择正在激活的拼音。
- 当前 ID 仍为其他来源时，允许有限重试。
- 用操作序号区分新旧计时器和回调，旧操作不得释放新队列、恢复旧来源或清除新状态。
- 快速重复 Shift 在已有切换期间合并处理，不堆积无限切换请求；具体响应体验在后续验证时记录。

原项目的 50ms 延迟、20ms 确认间隔、最多两次重选、600ms 暂存兜底只作为起始参考，不作为跨设备保证。实现前要明确原始 Shift-up 是放行还是暂存，不能同时假定它已经到达旧输入法、又把它留在队列中。

### 6.2 暂存与释放

仅在切换窗口内短暂保存普通输入及相关 Shift 事件；Command / Control / Option 快捷键优先放行。正式运行的键盘回调不睡眠或扫描窗口；显式调试模式会同步输出控制状态并追加诊断日志，因此调试模式不参与输入延迟和资源验收。

- 队列设置固定事件数量上限，初步取 128 条，计时器必须有总截止时间。
- 补发保留原顺序、按下/松开配对和修饰键信息；大写切换也必须考虑与该队列的先后关系。
- 超时、队列达到上限、切换失败或停止监听时，结束本次暂存并释放已持有事件，不无限等待或继续入队。
- 超限后的物理 key-up 与已经补发的 key-down 必须能正常配对；不能为“清空队列”直接丢弃输入。
- 外部输入法切换打断当前操作时，取消过期重试并结束暂存，避免下一次计时器把用户切回。

### 6.3 权限、退出和特殊环境

- 缺少辅助功能或输入监控权限时，终端给出缺失项和系统设置路径，避免空循环重试。无 GUI 指不创建自己的界面，系统授权界面仍由 macOS 提供。
- event tap 因超时停用时，清除不完整手势并有限恢复；持续失败则报告并退出，不高速重建。
- 安全输入期间放行，不记录输入内容；如果系统不向监听器暴露事件，不承诺该环境中的自定义快捷键可用。
- 睡眠唤醒或键盘重连后，清除未完成的 Shift 手势，重新读取必要的锁定状态；实际恢复途径按系统通知接入能力确定。
- 正常终止时释放监听、通知、计时器和持有事件；不随意把用户 Caps 状态强制关掉。进程异常退出时系统应继续正常接收原始键盘事件，不能依赖守护进程持续模拟按住某个键。
- 首版不承诺自动识别所有远程桌面和游戏。使用这些应用前可停止 KeyFlux；自动放行属于后续兼容性阶段，评估事件驱动的前台应用通知及其内存成本后再加入，不能定时遍历进程。

## 7. 15 MB 与低 CPU 的验收口径

15 MB 是必须验证的工程目标，不是“用了 Rust 就已经满足”的结论。

| 指标 | 约定 |
| --- | --- |
| 内存单位 | 十进制 15 MB，即 15,000,000 字节；不与 15 MiB 混用 |
| 主指标 | KeyFlux 单个进程的 RSS；空闲及正常连续切换阶段采样均以不超过 15 MB 为目标 |
| 辅助指标 | 记录 macOS 活动监视器内存 / physical footprint 与启动峰值，单独列出，不混用来宣称达标 |
| 采样条件 | 后续使用实际 Release 二进制；记录 macOS、架构、键盘、运行时间、日志模式与采样间隔 |
| 空闲 CPU | 接近 0；参考验收为静置 10 分钟平均不超过一个逻辑核的 0.1%，以实际工具口径说明 |
| 连续工作 | 后续人工验证连续切换与输入至少 30 分钟，记录最大采样 RSS、丢字、重复输入与切换失败 |
| 线程 | 程序只设计一个主要事件循环线程，不主动创建线程池；系统框架附带线程另行记录 |
| 空闲唤醒 | 没有定时输入法查询或应用扫描；切换操作结束后不留下重复计时器 |

进程内无法简单保证 macOS 所有瞬时内存分配永远低于固定上限，因此需要同时报告采样结果与测量限制。若实际达不到 15 MB，不将它写成已完成；先拆解框架加载、队列和分配成本，再讨论是否需要调整路线。

减小内存的主要手段：不初始化 GUI 框架、不读取图标、不缓存所有输入源对象、按需持有 ABC 与拼音标识、短生命周期查询结果及时释放、暂存队列有界、详细事件日志默认关闭。不通过定时退出重启或移出到第二个进程来掩盖内存。

Release 的 LTO、符号裁剪等只在后续确有需要时评估；可执行文件变小不等于 RSS 降低，不为追求体积提前修改整个构建配置。

## 8. 分阶段实施顺序与停止点

当前阶段 0～5 的主要代码已接入，并完成编译与纯逻辑验证。阶段 1 中涉及物理短按、IOKit 权限与键盘灯的部分仍待实机确认；阶段 3～5 也仍需真实输入框验收。不能把源码接通等同于全部功能可用。

Caps 长按只按每设备第一次按下翻转；安全输入与带快捷修饰键的 Caps 组合放行，恢复后重新读取真实系统 Caps。系统 flagsChanged 不被当作第二次物理开关；补发事件发送前按最新来源上下文处理 ABC 字母，避免在拼音→ABC 的等待期间提前固定错误大小写。退出时保留真实 Caps 状态，不模拟永久按住 Shift。

默认启动已经启用 Shift 切换。TIS 只枚举启用来源，并独立保留 ABC 与选定拼音两个来源引用。来源通知只标记状态并唤醒一次性处理，避免选择 API 同步通知时重入应用状态。切换触发的 Shift-up 原样放行；后续普通输入和 Shift 按需复制，最多 128 条、总截止 600ms。确认或取消后按原顺序补发，补发带自定义标记，不再次触发状态机。

切换期间重复单按 Shift 会合并，丢弃尚未送达的完整 Shift 手势，避免拼音把它解释成内部中英切换。快捷键、Caps 变化或外部来源变化可取消当前操作；队列达到上限或事件复制失败时释放输入并停止监听报错。空闲时计时器从 RunLoop 移除，不保留定时输入来源查询。逐事件诊断默认关闭，显式设置 `KEYFLUX_DEBUG=1` 才输出相关状态，不记录输入文字。

Shift 规则额外用固定大小位图记录普通键，处理“先按字母，再按 Shift”和普通键松开期间的组合输入。系统安全输入期间清除手势并放行；由于事件可能被系统隐藏，本阶段不承诺识别所有安全输入进入/退出边界。睡眠唤醒与外接键盘重连通知尚未接入，不作为已完成能力。

后续每次仅进入用户明确要求的阶段，说明涉及文件后再修改；不自动完成整个计划。

| 阶段 | 工作内容 | 完成条件 / 停止点 |
| --- | --- | --- |
| 0：方案 | 固定功能约定、范围和风险 | 形成当前文档，停止，不写实现 |
| 1：系统能力最小接入 | 权限检查、CFRunLoop、键盘事件分类；优先确认中/英键短按事件、真实 Caps 状态和可用 API | 能确定 Caps 路线及所需权限；只输出必要事件元信息，不输出实际输入文本；不顺带接入完整切换功能 |
| 2：Shift 状态机 | 左右 Shift、其他键/修饰键、鼠标计数、重复和缺失事件处理 | 状态与动作规则明确；暂不修改输入来源 |
| 3：ABC / 拼音接入 | 枚举并确认目标来源 ID、TIS 选择、系统变更通知 | 不把其他输入法当目标；诊断选择结果，不只判断 API 返回值 |

## 11. 2026-10-23 外接键盘短按与故障恢复修正

此前将 `IOHIDGetModifierLockState` 当作 setter 的对称回读，要求旧 IOHIDSystem 和会话同时匹配才确认。这不符合 [Apple IOHIDLib.c 的实现](https://github.com/apple-oss-distributions/IOKitUser/blob/main/hidsystem.subproj/IOHIDLib.c)：setter 写入各键盘服务的 `HIDCapsLockState`，getter 读取旧 IOHIDSystem 状态。现在确认条件改为所有键盘服务属性一致且会话匹配；旧读数保留诊断，不再单独导致失败。服务属性未读到、类型不符或设备间不一致均不视为成功，不退回只检查会话的旧方案。

属性查询使用 IOKit 导出的服务 SPI，隔离在原生适配层。Passive 客户端类型及 CopyProperty 声明核对 [WebKit IOKitSPIMac.h](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/PAL/pal/spi/mac/IOKitSPIMac.h)，属性名核对 Apple IOHIDProperties.h。本机只读探测成功读取四个键盘服务的布尔属性；每次查询获取新的服务快照并及时释放，不增加空闲轮询。SPI 的跨 macOS 版本兼容性仍需发行前验证。

[Apple 键盘过滤器](https://github.com/apple-oss-distributions/IOHIDFamily/blob/main/IOHIDEventSystemPlugIns/IOHIDKeyboardFilter.mm) 默认 Caps 开启延迟为 75ms。故障记录约 68ms 的短按没有原生开启事件，与这一机制相符；这仍是对外接键盘触发条件的解释，未测定该设备实际配置。没有修改系统延迟或键位映射。

短暂状态不同步继续使用原有有界确认。耗尽后，在当前回调返回后释放 tap、HID、输入源通知、计时器及 IOHIDSystem 连接，再于 250ms 后重建；延续尚未确认的 Caps 目标。持续故障采用 1s、3s、10s、30s 间隔，之后保持每 30s 自动尝试，不因次数达到四次永久停止。稳定监听 60s 后下一次故障恢复到首档。正常监听期间恢复计时器不注册在 RunLoop 中。

菜单显示“正在恢复监听”，恢复过程不弹模态报错。手动停止、退出会取消恢复和旧故障信号；权限失效、输入源配置缺失或 Rust 回调 panic 暂停自动恢复，并保留菜单和日志原因。后台恢复不主动弹出权限申请。

纯逻辑回归覆盖服务与会话确认、旧 IOHIDSystem 不一致、未知服务状态、持续故障退避、手动停止、稳定后重置及恢复 Caps 目标。实际外接键盘快速连按、恢复时输入和资源占用仍需新版 Release 实机验证；未宣称已达到 15 MB，也未制作新 DMG。
