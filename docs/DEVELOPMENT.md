# KeyFlux

使用 Rust 实现的 macOS 输入增强工具，目标是单按 Shift 切换 ABC / Apple 拼音、中/英键短按锁定大写。当前改为菜单栏常驻，先完成实机测试，本次不制作 DMG。

Shift 切换与中/英键短按大写仍需实机验收；菜单栏完成不代表键盘效果或 15 MB 内存指标已通过。

## 当前：菜单栏后台运行

没有主窗口，Dock 不显示图标，仅保留顶部菜单栏的单色 **⇧**。直接执行开发二进制也采用此模式，无需生成 App 或 DMG。菜单栏图标的具体位置由 macOS 管理。

修改源码后需要自行重新构建，在 KeyFlux 项目目录运行：

```sh
cargo build --release
./target/release/KeyFlux >> target/keyflux-runtime.log 2>&1
```

需要终端立即返回时，在启动命令末尾加 `&`。终端启动仍需保留终端会话；后台运行不等于开机自启。

状态、权限和使用说明直接显示为子菜单，不创建应用内弹窗，也不抢占焦点；权限齐全时直接启用键盘切换。菜单栏使用 15 pt 的文字 ⇧、基线下移 1 pt、22 pt 固定占位，以动态系统文字色适配深浅背景；不加载系统图片符号。使用前请关闭系统自带的中/英键切换输入法选项，设置方法可从 ⇧ 菜单“使用说明”查看。缺权限时保留菜单栏等待用户授权，可选择“检查权限并启用…”。需要先采集暂停状态基线时，运行 `./target/release/KeyFlux --paused`。

左击或右击 **⇧** 打开菜单：

- **启用键盘切换 / 暂停键盘切换**：控制 Shift / Caps 切换，暂停后保留菜单栏进程。
- **检查权限并启用…**：重新检查权限；权限齐全后启用键盘切换。缺权限时显示说明，并可打开相应设置。需要多个权限时，开启一项后可再检查下一项；系统要求重启时从菜单退出后重新运行。
- **打开键盘设置…**：手动关闭系统中/英键切换选项；程序不修改该设置。
- **登录时自动启动**：点击勾选 / 关闭，修改当前用户下次登录时的启动配置；当前进程继续运行。配置状态与错误原因可在“状态与权限”中查看。
- **状态与权限**：子菜单中查看当前状态、最近消息和三项权限；长消息可停留查看提示，并可直接打开系统权限设置。
- **使用说明**：按需查看系统中/英键设置方法。
- **退出 KeyFlux**：先停止并清理监听，再退出进程。

监听故障后会释放旧资源并自动重建，恢复中在菜单显示状态，不弹模态报错。持续故障逐步退避到每 30 秒尝试；手动停止、退出会取消恢复。权限失效、输入源缺失或回调 panic 需用户处理，原因保留在状态与日志中。不增加正常空闲时的轮询。

### 登录时自动启动

默认不创建自启配置；需要时从 ⇧ 菜单手动开启。使用当前用户的 macOS LaunchAgent，在下次登录图形会话时启动一份 KeyFlux；不需要管理员权限，不增加常驻辅助进程、定时检查或异常退出后的系统自动拉起。

- 配置文件：`~/Library/LaunchAgents/org.keyflux.KeyFlux.login.plist`，仅在用户点击开关时修改。关闭时将本配置设为禁用，不删除配置，也不结束当前程序。
- 命令行开发版保存当前可执行文件的绝对路径；App 版通过 `/usr/bin/open -g` 打开完整 App，保持 Launch Services 启动方式。不要把临时构建目录或挂载的 DMG 当成长期安装位置。
- 项目 / App 移动后，菜单会提示“点击更新路径”；再次点击更新为当前版本的位置。切换到其他版本时也应检查此状态，避免登录时打开旧版本。
- 自启日志：`~/Library/Logs/KeyFlux/KeyFlux.log`。默认不启用逐按键调试，也不保存本次手动暂停状态；下次启动按现有规则检查权限，权限齐全时启用键盘切换。
- 勾选表示 KeyFlux 的配置已开启，不代表已经通过系统的后台项目许可。若系统设置禁用了该项目，需要在“系统设置 → 通用 → 登录项与扩展”中允许；系统的限制优先。首次独立启动后的键盘权限仍需实机确认。
- 状态仅在打开菜单 / 点击开关时检查，不新增轮询或依赖。实际内存变化、开启 / 关闭后重新登录的效果尚待实测，不据此宣称 15 MB 已达标。

直接运行开发二进制仍可能由 Warp / RustRover 承担权限。需要用独立身份验证时，只生成开发 App：

```sh
python3 scripts/package_macos.py --app-only
```

打开脚本输出的 `target/dev-apps/…/image/KeyFlux.app`，不要打开旧 DMG 或旧安装版。此模式不创建 DMG，不安装，也不自动启动 App。

菜单栏与提醒使用 `objc2` / AppKit 的 Rust 绑定，仍为单进程。AppKit 加载会影响内存；此前 15 MB 是早期无 AppKit 阶段的设计目标，当前版本需要按整个进程重新测量，不宣称已达标。

## 后续 DMG 安装方式（本次不制作）

后续重新测试并打包后，把 `KeyFlux.app` 拖入“应用程序”，再双击打开。权限齐全后，开始菜单栏后台监听。

首次启动会请求系统权限。在“隐私与安全性 → 设备控制和数据访问”（旧版为“辅助功能”）以及“输入监控”中允许 **KeyFlux**，然后重新双击打开。应通过 Finder / Launch Services 启动整个 App；直接执行包内二进制仍可能将权限归属到启动它的终端。

使用前启用 ABC / Apple 拼音并关闭下文的系统中/英键切换选项。测试前退出旧版本。新版本用进程文件锁避免同一用户重复运行；登录自启需从菜单手动开启，通过菜单栏的“退出 KeyFlux”退出。App 日志位于 `~/Library/Logs/KeyFlux/KeyFlux.log`。

App 默认关闭逐事件诊断。排查时先退出已有 KeyFlux，再运行：

```sh
open -a /Applications/KeyFlux.app --args --debug
tail -f ~/Library/Logs/KeyFlux/KeyFlux.log
```

其中 `open` 通过 Launch Services 启动 App；不需要给每个终端重复授权。授权对象和新版系统兼容性仍需在安装后的 App 中验收。

本机打包使用 Python 3.9+ 与 Rust 1.89+，不需要 Python 第三方库：

```sh
python3 scripts/package_macos.py
```

脚本在 `dist/` 新建唯一目录，生成本机架构的 App、DMG、安装说明和 SHA-256，不覆盖旧包、不安装或启动程序。默认产物为本地 ad-hoc 签名，**未公证，供本机验证**。固定 Bundle ID 不能代替签名证书；跨版本更新仍可能需要重新授权。公开发行使用维护者自己的 Developer ID 和公证流程，见 [发行说明](DISTRIBUTION.md)。

## 中/英键大写控制

实机使用前，请手动到“系统设置 → 键盘 → 文字输入 → 编辑 → 所有输入法”，关闭“使用大写锁定键 / 中英键切换至和切换自……”选项。开启该选项时系统也会处理语言切换，可能与 KeyFlux 同时响应；程序不自动修改此项。[Apple 输入法设置说明](https://support.apple.com/zh-cn/guide/mac-help/mchl84525d76/mac)

- 使用非独占 IOHIDManager，只订阅键盘 Caps Lock 的 UsagePage=7、Usage=0x39；不读取普通字母内容、不独占设备，不安装驱动。
- 每个设备的一次物理按下只翻转一次。长按重复报告、启动前的旧报告、安全输入和带 Command / Control / Option 的 Caps 组合，不作为新的大写开关。
- Caps 松开后由 RunLoop 计时器确认所有键盘服务的 `HIDCapsLockState` 属性与当前输入会话达到目标。旧 `IOHIDGetModifierLockState` 读取不同通道，仅作诊断，不能代替 setter 实际写入属性的确认。每轮 300ms、最多写 4 次、间隔至少 20ms；失败后等待 100ms、200ms 进入后续两轮，最多累计写 12 次。耗尽后保留故障记录并自动重建监听，不永久停止。新目标替换旧重试，用户停止或安全输入会取消重试。普通 Shift 中英切换不主动写 Caps，空闲时不轮询。键盘灯、输入框是否真正进入拼音组词仍需实机验收。
- 三个目标状态为中文拼音、小写 ABC、大写 ABC。拼音或小写 ABC 下按 Caps 进入大写 ABC；大写下再按 Caps 固定进入小写 ABC。Caps 不保存或恢复旧拼音，进入拼音由单按 Shift 完成。
- Caps 开启时，单按并松开 Shift 关闭大写、留在小写 ABC，不恢复原拼音；再单按 Shift 才进行普通中英切换。ABC 下 Caps+Shift+字母输出临时小写，组合输入不触发这个单按动作；数字、标点及带快捷修饰键的事件不做字母重写。
- 安全输入期间不执行大写接管，恢复后读取真实系统状态；退出时不强制关闭用户 Caps Lock。运行期间 Caps 由 KeyFlux 管理，不应假设与其他 Caps 重映射工具的状态修改可以叠加。

HID 报告、IOHIDSystem 写入权限、键盘灯同步和应用是否采用修改后的 Unicode 字段，都必须在实机验证，编译与逻辑测试不证明这些能力已在本机生效。

设置环境变量 `KEYFLUX_DEBUG=1` 后，源码启动会同时输出到终端，并追加保存到当前项目的 `target/keyflux-debug.log`。包含时间戳、进程号、Shift 判定动作、来源切换请求 / 确认 / 取消、Caps 期望值、IOKit 与会话状态对照。普通字母键码和输入文字不输出，暂存的原生事件不写入文件。诊断模式会增加日志开销，不用于内存、CPU 或延迟验收。

复现后无需安装或生成 App，保留日志即可分析：

```sh
KEYFLUX_DEBUG=1 cargo run --release
# 另一个终端查看
tail -n 100 target/keyflux-debug.log
```

菜单“状态与权限”显示三项独立权限查询结果；从菜单检查时，缺权限会请求系统授权提示并提供设置入口，由用户自行开启。直接从终端运行仍受启动应用和签名影响。

队列溢出或无法复制原生事件时，会取消本次切换、尽力按顺序释放输入并停止监听报错，避免无限缓存。快捷键或 Caps 状态变化会取消尚未完成的切换，并将已暂存事件排在当前事件之前补发。来源通知若显示用户已经选择其他来源，会取消旧操作，不持续抢回输入法。

来源 ID 与选中状态确认，只能证明系统来源选择完成，不能替代目标应用实际输入验证。原项目的透明窗口焦点修复没有移植；若某个输入框图标变化但仍输入英文，需要记录具体应用再处理。下一阶段统一进行实机键盘 / 输入框与资源验收。

## 一天使用的性能记录

KeyFlux 已在运行时，只需在另一个终端标签页启动采样器，不需要重启 KeyFlux、重启电脑或重新打包。下列脚本为独立 Python 进程，不更改自启设置或键盘行为。

只有 KeyFlux 尚未运行时，才在终端一启动程序；关闭详细诊断和分配跟踪，将基础日志追加到文件：

```sh
unset KEYFLUX_DEBUG MallocStackLogging MallocStackLoggingNoCompact
./target/release/KeyFlux >> target/keyflux-runtime.log 2>&1
```

终端二进入项目根目录，确认菜单栏状态为“已启用”，运行全天采样：

```sh
python3 -B scripts/monitor_keyflux.py --interval 30 --hours 24 --follow-restarts --tag normal-day
```

仅需 Python 3.9+ 标准库，无需安装依赖、sudo 或额外键盘权限。默认每 30 秒读取一次，最长 24 小时；每次附加后的前 120 秒单独标记为预热，原始样本仍保留。`--hours 12` 可改为 12 小时。每 5 分钟显示一次终端状态并保存摘要；状态变化和故障另行提示。不能把脚本启动当成键盘功能已启用。

`--follow-restarts` 只会等待并附加同一项目、同一可执行路径的新进程，不会替用户启动程序。每次附加单独分段并重置 CPU 基线、预热和故障计数；跨进程不计算内存首末增长。进程中断会明确记录，即使后来重新运行也不能算无故障。不加此参数时，目标退出 / 身份变化会结束采样并返回非零退出码。

采样器只附加当前项目的 `target/release/KeyFlux`；独立安装 App 的其他可执行路径不在本次采集范围。默认自动识别终端 / 登录自启两份控制日志：`target/keyflux-runtime.log` 和 `~/Library/Logs/KeyFlux/KeyFlux.log`。只接收对应 PID / 启动时间的控制记录，重复日志去重，不复制逐按键、设备或输入文字诊断。找不到状态或发生日志丢失时标记 unknown / 覆盖不完整，不把缺少日志当作没有故障。自定义重定向路径可通过 `--runtime-log "/绝对路径/KeyFlux.log"` 指定；该参数可重复，此时以指定路径替代默认路径。

每次新建独立目录 `target/performance/日期时间-pid进程号-随机后缀/`，不覆盖之前的数据：

| 文件 | 内容 |
| --- | --- |
| `samples.csv` | 时间、采样跨度、区间 CPU、累计 CPU 时间、RSS、物理 Footprint、线程数、空闲 / 中断唤醒计数、page-in 计数、累计磁盘读写字节 |
| `events.jsonl` | 开始 / 结束、内存目标跨越、睡眠 / 采样空档、进程退出与等待、状态变化、日志缺失 / 轮转，以及采样器自身 CPU 时间和内存峰值 |
| `metadata.json` | PID、程序路径、附加时磁盘二进制 SHA-256、系统 / 架构、采样参数和内存口径 |
| `keyflux-runtime.log` | 自动 / 指定来源中本次附加后的控制记录，按 PID / 启动时间过滤并去重；未记录到日志时可能为空 |
| `summary.txt` / `summary.json` | 附加时、每 5 分钟和结束时保存：均值、P95、采样峰值、同进程首末变化、达到或超过目标的样本数，以及按进程 / 小时分组的数据 |
| `hourly.csv` | 每个采集小时的 CPU 加权均值、内存均值 / P95 / 采样峰值；跨小时区间按结束样本归属，CPU 空档排除 |
| `segments.json` | 每次附加的 PID、启动时间、二进制哈希、初始状态、结束原因和本段计数 |
| `runtime-status.json` | 各进程附加后故障 / Caps 额外确认 / 自动重建次数合计、当前状态及日志覆盖是否完整 |
| `notes.jsonl` | 用户手动添加的异常时间、使用场景或体感备注；不会自动采集窗口或输入内容 |

内存按 **MB = 1,000,000 字节**，RSS 和 Footprint 分开判断，默认严格小于 15 MB；P95 采用最近秩法。CPU 按累计用户 / 内核 CPU 时间的增量计算区间平均，100% 表示一个逻辑核；不是进程从启动至今的平均 CPU。内存峰值是采样观测峰值，不能排除两次采样之间的瞬时峰值。CPU 汇总按有效区间时长加权，结合两种 Mach 时钟识别超过约 1 秒的系统睡眠，相关区间和较长调度空档单独记录，不当成空闲 0%。功能状态或预热边界发生变化的区间，不混入对应的稳定状态 CPU 统计。

脚本属于独立 Python 进程，不计入 KeyFlux 的进程数据，它自身的开销另记在结束事件中。脚本不读取按键、输入文字或窗口内容，也不上传日志。CSV 增加来自日志的监听状态和故障计数，报告单独汇总“预热后监听样本”；日志缺失时标为 unknown。自动恢复成功仍计作发生过故障，不能仅凭最终仍在监听就验收通过。进程消失不能直接断言是崩溃，一次运行的内存增长也不能单独证明泄漏。

终端标签页保持打开，可最小化；不需要禁用电脑睡眠。**一天结束后在采样终端按 Ctrl+C，只结束采样并保存报告，不会退出 KeyFlux。** 达到时长也只停止采样。正常的 Ctrl+C、终止信号和终端挂断会尝试保存最终报告；强制杀死或断电时仍保留已写入的 CSV、事件及最近摘要。关闭终端、注销或重启电脑会结束采样进程，跟随模式不能跨电脑重启自动恢复。

采样尚未结束时，也可以在第三个终端读取当前报告，使用采样器打印的实际目录：

```sh
python3 scripts/monitor_keyflux.py --report "target/performance/实际采样目录"
```

发现异常时，可在另一个标签页追加备注，用采样器打印的实际目录：

```sh
python3 -B scripts/monitor_keyflux.py --report "target/performance/实际采样目录" --note "外接键盘，某应用，Caps 切换异常，稍后自行恢复"
```

备注自动带当前时间；不方便当时记录也可自行记下准确发生时间。不要填写输入文字或敏感内容。

一天结束后在采样终端按 Ctrl+C，保留整个目录。提供目录路径及体感：有无漏字、误切、延迟或功能停止，大致时间、应用名称和键盘类型。现有 CSV 可重新生成报告，最后一行未写完整时会提示并忽略；旧版数据仍可读取。基础日志和性能日志均不代表实际按键效果自动验收，也不能仅凭内存增长断言泄漏。

## 新版先进行短测

关闭 Instruments / 分配跟踪，用正常模式做 10～15 分钟短测，之后再做全天采样。先从 ⇧ 菜单退出旧进程，在 Warp 项目目录启动新版：

```sh
unset KEYFLUX_DEBUG MallocStackLogging MallocStackLoggingNoCompact
./target/release/KeyFlux --paused >> target/keyflux-runtime.log 2>&1
```

另一标签页执行：

```sh
python3 -B scripts/monitor_keyflux.py --interval 2 --hours 0.25 --warmup 10 --tag optimized-normal-external
```

1. 暂停键盘切换后静置 60 秒，记录菜单栏基线。
2. 从 ⇧ 选择“启用键盘切换”，保持空闲 60 秒。
3. 外接键盘两批各 20 次 Caps、50 次单按 Shift。检查三状态路径、实际中文候选、大小写与快捷键，再验证内置键盘。
4. 浏览“状态与权限”和“使用说明”子菜单各两次，收起菜单后静置 60 秒，记录正常查看界面后的内存表现。
5. 选择“暂停键盘切换”、保留进程，静置 60 秒；在采样终端按 Ctrl+C，生成报告。手动暂停后不能自行重新启用。

若有异常记下时间和现象；即使自动恢复也算发生过故障。短测不使用 vmmap / heap / malloc_history，减少诊断工具对按键时序和内存的干扰；需要继续定位时再单独运行下文快照。RSS 与 Footprint 都保留，不能把其中一项低于 15 MB 写成全部达标。短测正常后按默认 30 秒间隔运行一天。

## 分阶段定位内存来源

当前使用菜单栏 ⇧ 控制开始、停止和退出。诊断脚本会在采集前后检查 `target/keyflux-runtime.log` 中当前 PID 的监听状态；需按前文命令重定向启动日志。状态不明或切换测试期间监听停止时，中止并保留已采集数据，不把后续阶段当作有效压力测试。

Caps 同步等待最后一个物理 Caps 松开后才启动写入与确认计时。正常确认期间不重新注册监听、不创建额外线程，来源流程由 Caps 确认完成主动唤醒；耗尽后才输出固定容量的最近 24 条控制记录并重建监听。键盘服务属性与会话必须达到目标，不记录文字、不增加空闲轮询。外接键盘短按效果仍需单独实测。

以下旧快照流程按控制窗口版本设计；当前菜单栏版本没有窗口，基线应改为菜单栏停止监听状态，开始 / 停止通过 ⇧ 菜单操作。旧测量结果不能直接作为新版结果。

全天采样给出总量；要区分窗口基线、监听资源和反复切换后的增长，运行独立快照脚本。不需要重新编译，不自动控制 GUI，不开启分配跟踪或制作 DMG。

先打开当前 Release 版本并关闭详细诊断；若已经在运行，直接使用同一个进程，不必重启。然后在项目根目录的另一个交互式终端执行：

```sh
python3 -B scripts/profile_memory.py
```

脚本自动查找当前项目的 KeyFlux，依次提示：

1. 保持菜单栏进程运行、停止监听，静置 120 秒，取得基线。
2. 手动开始监听，静置 30 秒。
3. 在常用输入框完成一批切换，建议单按 Shift 50 次、Caps 20 次，之后静置 30 秒。
4. 在同一输入框完成相同次数的第二批操作，之后静置 30 秒。
5. 手动停止监听、保留菜单栏进程，再静置 30 秒。

每阶段完成后回到终端，输入操作次数、使用应用、异常等备注（可留空），按回车采集。请保持同一个 KeyFlux 进程，不关闭窗口、不重新编译；备注不要填写输入文字或敏感内容。最后阶段会按你的操作保留在停止监听状态，脚本不会自动恢复监听，需要继续使用时自行点击开始。

快照工具可能短暂影响输入响应，采集时先暂停按键，等脚本提示保存完成再继续。`--settle 60` 可增加阶段间静置时间。脚本按 Ctrl+C 可提前结束，只保存已采集部分，不改变应用状态。

每次在 `target/memory-profile/日期时间-pid进程号-随机后缀/` 新建独立目录：

- 各阶段 `*-vmmap.txt`、`*-footprint.txt`：系统内存区域分类原始输出。
- 各阶段 `*-metrics.json`：工具运行前后的 RSS、Footprint、线程数，以及工具返回码和耗时。
- `comparison.md` / `comparison.csv`：工具运行前的阶段数值及相邻阶段差值。
- `metadata.json`、`notes.jsonl`、`result.json`：进程身份、附加时二进制哈希、人工备注和完成状态。

默认不执行泄漏扫描。确有需要时可加 `--leaks`，仅在最后阶段运行 `leaks --noContent`，不输出对象内容或生成堆内存图。工具超时或权限不足会保留错误，不自动 sudo、修改签名或重复尝试。即使阶段指标成功，工具失败仍意味着尚未获得该工具的内存分类证据。

这些快照用于缩小范围，不能直接定位到 Rust 分配调用栈。阶段差值也包含缓存、初始化和系统回收，不能直接等同于某模块独占内存或泄漏量；需结合相同操作的多批结果判断，再决定是否启用单独的分配跟踪。诊断期间的内存不作为正常运行 15 MB 指标的验收值。

## 项目结构

| 位置 | 职责 | Java 项目中的近似角色 |
| --- | --- | --- |

| `src/application/` | 启动流程、输入切换用例协调 | 应用 Service |
| `src/presentation/` | 菜单栏操作与监听生命周期协调 | 桌面界面 Controller |
| `src/domain/` | 纯按键状态规则、输入来源模型 | 领域对象与规则 |
| `src/infrastructure/macos/` | 键盘事件、输入法、权限和系统事件循环 | 操作系统 Adapter |
| `src/error.rs` | 统一错误类型与 Result 别名 | 项目异常定义 |
| `docs/PLAN.md` | 行为约定、技术方案、实施阶段与验收要求 | 技术设计文档 |
| `docs/THIRD_PARTY_NOTICES.md` | 原项目许可与版权声明 | 第三方许可记录 |
| `packaging/macos/` | 独立后台 App 描述与 DMG 安装说明 | 发行资源 |

Rust 源码仍按 Cargo 约定位于 `src/`，通过目录与 `mod.rs` 声明模块边界。当前是单个二进制 package，不包含 Web 接口或数据库，不设置对应的 Controller / Mapper 层。

## 依赖与职责边界

```text
main
  └── bootstrap：创建对象并组装依赖
        └── application：协调应用流程
              ├── domain：纯模型与状态机
              └── infrastructure/macos：系统能力适配
```

- `domain` 不引用 `application` 或 `infrastructure`，不出现 macOS FFI。
- `application` 使用领域规则与系统适配器组织流程，不声明原生 FFI。目前使用具体适配器，尚未引入 trait 端口。
- `infrastructure/macos` 可以使用领域模型与统一错误，不反向调用应用层；通过回调或事件接口报告系统变化。
- `bootstrap` 负责创建对象并传入应用层；Rust 不会像 Spring 一样自动扫描和注入对象。
- FFI、`unsafe` 与原生对象的创建/释放集中在 macOS 适配目录；原生回调不包含业务流程。

新增功能时，先确定它属于规则、流程还是系统适配，再放到对应目录。当前无需按文件拆分成多个 crate，也不预建没有实际用途的目录。
